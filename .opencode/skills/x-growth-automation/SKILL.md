# X Growth Automation & Multi-Account Engine

This skill governs multi-account X (Twitter) growth operations, hybrid browser + API automation, viral mention-triggered demo bots, and live CRM dashboard synchronization.

## 1. Dual-Account Architecture
When operating multiple X accounts in parallel:
- **Operator Persona (`@adnanspitch`):** Focused on outreach, lead prospecting, and builder community engagement.
  - Isolated browser profile: `.browser-profile-adnanspitch/storageState.json`
- **Official Brand (`@trypitchdotco`):** Focused on product posts, 30–60s video walkthroughs, and official API replies.
  - Isolated browser profile: `.browser-profile-trypitchdotco/storageState_trypitchdotco.json`
  - Official X API v2 Wrapper: `bin/xurl-pitch` (features automatic OAuth 2.0 token refresh via `POST /2/oauth2/token` when access token expires after 2 hours)

## 2. Safety & Verification Gate
Before taking ANY public action:
1. Navigate to `x.com/home` and read the logged-in handle.
2. Assert active handle matches target account handle (`@adnanspitch` vs `@trypitchdotco`).
3. If handles do not match or account is logged out, **IMMEDIATELY ABORT** session (`circuit-breaker.sh --trip`) without taking any actions.

## 3. Hybrid Mention Demo Bot Pattern & Direct Pitch MCP Integration
For viral mention-triggered video generation on X (`@trypitchdotco make a demo for [URL]`):

### Strict Mention Filtering
- **Category A: Mention WITH Product URL/Domain** (`@trypitchdotco make a demo for tella.com`): Triggers instant acknowledgment and video generation via Pitch MCP API.
- **Category B: Mention WITHOUT Product URL/Domain** (`@trypitchdotco thanks!`): Does NOT trigger video rendering. Replies with helpful instruction: *"Hey @username! Mention us with any product URL (e.g. `@trypitchdotco make a demo for myproduct.com`) and I'll generate a cinematic video demo for you! 🎬"*

### Default Parameter Presets
When invoking `create_demo_video` on Pitch MCP (`https://api.trypitch.co/mcp`), supply the complete parameter schema with default presets:
```json
{
  "url": "https://target-url.com",
  "instructions": "Create a cinematic, polished product demo of [URL]. Highlight key features, value proposition, and user experience.",
  "voice": "Charon",
  "subtitles": false,
  "theme": "light",
  "background": "ocean",
  "shape": "rounded",
  "inset": "0.75",
  "browserHeader": "light"
}
```

### Instant Receipt + Rendered S3 Video Reply Flow
1. **Instant Receipt Reply (<1 Second):** As soon as a valid mention with a URL/domain is received, send an immediate acknowledgment reply on X via official API (`xurl-pitch`):
   *"Cool @username, we're on it! 🚀 Generating your cinematic demo for [URL] now, we'll get back to you with the video link right here soon!"*
2. **Direct MCP Job Creation:**
   ```bash
   python3 /home/adnan/x_bot/bin/pitch_mcp.py create "[TARGET_URL]"
   ```
   Calls `create_demo_video` on `https://api.trypitch.co/mcp` and returns `jobId`.
3. **Job Progress Polling:**
   ```bash
   python3 /home/adnan/x_bot/bin/pitch_mcp.py status "[JOB_ID]"
   ```
   Polls job phases (`workspace_init`, `video_recording`, `ffmpeg_postprocessing`, `intro_outro`) until `COMPLETED`, returning the final `final_with_cards.mp4` S3 URL.
4. **Final Rendered Video Reply:**
   - Tag the requesting user (`@username`) directly in the reply text.
   - Format: *"Here is your product demo @username generated by @trypitchdotco! Hope you enjoy it: https://s3.trypitch.co/.../final_with_cards.mp4 🎬"*
   - First attempt native MP4 video upload via `xurl-pitch media upload video.mp4` and attach media ID.
   - Fall back seamlessly to text reply with direct `final_with_cards.mp4` S3 link if native upload fails or times out.

- Serverless Sync Architecture: Local client scripts (`sync_supabase.py`) delegate sync to `/api/sync` on Vercel, which normalizes activity signatures (`ts + action + handle + cleanDetail`) to prevent duplicate record accumulation.
- Automated Deduplication: `GET /api/sync` serves as an automated database cleanup engine to purge historical duplicate rows in Supabase.
- Live Vercel Dashboard at `https://dashboard-blue-five-75.vercel.app` is protected by a Password Firewall Gate (`pitch@123` via `/api/auth`).

- Displays live logged-in badges, Kanban pipeline, and direct `Play S3 MP4 Video` render links.
- Manual Deletion: Every row features a Delete button (`/api/delete`) that removes entries from Supabase and issues `cancel_job` or `delete_job` to Pitch MCP.

## 5. High-Availability Multi-Tier Mention Architecture, Dual-Scan & Event-Driven Queue
1. **Tier 1 (Instant Webhook - <0.5s):** Native X Webhook Receiver on Vercel (`/api/x-webhook`) handles CRC challenge verification (`X_API_SECRET`) and writes incoming mentions to Supabase `mention_jobs` (`status: 'pending'`).
2. **Tier 2 (Real-Time Dual-Scan Fallback Daemon):** Persistent background daemon (`bin/mention_daemon.py`) scans **both** `x.com/notifications` and `x.com/search?q=%40trypitchdotco&f=live` every 10 seconds without artificial slicing (`[:20]` elements).
3. **Tier 3 (Unified Bidirectional Queue Worker Daemon - `bin/mention_mcp_worker.py`):** Single background worker constantly polls Supabase and Pitch MCP:
   - **Direction A (Supabase → Pitch MCP):** Claims `pending` mentions $\rightarrow$ triggers Pitch MCP `create_demo_video` $\rightarrow$ sets `status: 'rendering'`.
   - **Direction B (Pitch MCP → X Reply & Supabase):** Polls `rendering` jobs $\rightarrow$ retrieves final S3 MP4 URL $\rightarrow$ posts X reply to requesting user $\rightarrow$ sets `status: 'delivered'`.

## 6. Official X API Priority, Hourly Token Refresher & Playwright Fallback
To avoid account blocks or spam detection associated with browser automation:
- **Primary Execution Channel:** Always use the official X API v2 (`Authorization: Bearer X_USER_ACCESS_TOKEN` via `xurl-pitch` or direct HTTP request) as the primary engine for all original posts, quote tweets, and mention replies.
- **Automated Hourly Token Refresher (`bin/refresh_x_token.py`):** Runs periodically (every 45–60 minutes) to exchange OAuth 2.0 refresh tokens at `https://api.twitter.com/2/oauth2/token` and keep `.env` credentials continuously fresh.
- **Secondary Browser Fallback Only:** Playwright browser automation (`storageState.json` / `storageState_trypitchdotco.json`) is strictly reserved as a secondary fallback when the official API returns unrecoverable HTTP 401/403/429 errors.
- **Universal Idempotency Across All Actions:**
  - **Single Worker Process Pattern:** Use a single, dedicated background worker process (`bin/mention_mcp_worker.py`) per pipeline to handle both job creation and delivery state transitions, preventing multi-agent race conditions.
  - **Mention Jobs Idempotency:** Primary key `tweet_id` (e.g. `2086533777963270217_supermemory`) with Supabase `UNIQUE(tweet_id)` constraint.
  - **Posts, Quotes, Replies & DMs Idempotency:** Serverless `/api/sync` normalizes signatures (`YYYY-MM-DD` + `action` + `handle` + `cleanDetail`) before inserting to Supabase `activities`.
  - **Spaced URL Normalization:** Users frequently type URLs with spaces (e.g. `https:// supermemory.ai`). Always normalize spaced URLs (`https:// supermemory.ai` -> `https://supermemory.ai`) before running domain checks.
  - **Log ALL Mentions:** Mentions without a product URL are logged with `status: 'no_url_found'` and `target_url: 'N/A'` so operators can see 100% of mentions in the dashboard.

## 7. Real-Time Agent System Health, Daemon Monitor & Dynamic Heartbeat Detection
- **Dynamic Heartbeat Architecture:** Daemons (`mention_daemon.py`, `mention_mcp_worker.py`) periodically send heartbeat pulses (`action: 'heartbeat'`) to `/api/sync`.
- **Backend Health Check (`/api/stats`):** Checks the `last_pulse` timestamp for each daemon against a 60-second activity threshold. If a background process stops or is terminated, its status automatically transitions to **`STOPPED`** (`Offline`).
- **Dashboard UI Component:** Renders dark-themed agent status cards with live pulsing indicators (`ACTIVE` vs `STOPPED`) in the dashboard header, updating automatically every 10 seconds.
- For complete agent health monitoring specifications, see `references/realtime-agent-health-monitor.md`.

## 8. 24/7 Background Lead Researcher Daemon (`bin/researcher_daemon.py`)

## 9. Pure Rust Architecture (`pitch-cli`), Tmux Terminals, Zero-Supabase Direct Proxy & Local Git Policy
- **Rust Engine (`pitch-cli`):** On the `rewrite/clean-slate` branch, the entire backend is compiled into a single Rust binary (`pitch-cli`) with an embedded Axum HTTP server (`port 8790`), SQLite memory (`data/pitch_bot.db`), and native X API v2 / Pitch MCP clients.
- **Config Override:** Uses `dotenvy::from_path_override(&env_path)` in `src/config.rs` so updated `.env` values accurately reload.
- **Detached Tmux Agent Sessions & Tiled 4-Pane Dashboard:** Run agents inside named tmux sessions (`pitch-server`, `pitch-trigger`, `pitch-discover`) with `; exec bash` so processes stay open for inspection. Attach to the split-screen tiled view with `tmux attach -t pitch-dashboard`.
- **Spaced URL Normalization:** Mention tweets often contain spaces in URLs (e.g. `https:// supermemory.ai`). Always normalize URLs with spaces (`https:// supermemory.ai` -> `https://supermemory.ai`) before running domain checks.
- **Zero-Supabase Vercel Proxy Architecture:** To eliminate Supabase cloud database 100%, expose local Axum server (`port 8790`) over HTTPS tunnel (`localtunnel` / `cloudflared`) and configure Vercel API endpoints (`crm.js`, `mentions.js`, `stats.js`, `insights.js`, `auth.js`) to proxy directly to local Axum server routes (`/api/crm`, `/api/mentions`, `/api/stats`, `/api/insights`).
- **Playwright Search Fallback:** When X API search endpoint returns 401/403, `XApiClient.search_recent` automatically falls back to Playwright browser search (`https://x.com/search?q=...&f=live`), extracts live founder tweets, scores ICP fit, and saves leads to SQLite `data/pitch_bot.db`.
- **Local Git Verification Policy:** Test and verify all code changes locally first. Do NOT automatically execute `git push` to GitHub unless explicitly directed by the user.
