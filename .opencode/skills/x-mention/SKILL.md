# @trypitchdotco Viral Mention-Demo Bot Playbook

This playbook operates @trypitchdotco's automated viral mention demo bot using
**Instant Acknowledgement** + **Pitch MCP API (`https://api.trypitch.co/mcp`)**
+ **agent-webbridge** (real Chrome, `Testing` profile) for all X posting.

## Instant Receipt & Delivery Sequence

1. **Step 1: Instant Receipt Reply**
   - As soon as a user tweets `@trypitchdotco` with a product URL/domain, post an
     instant ack reply on X **through the agent-webbridge browser** (`Testing`
     profile) — drive the X post composer as in the x-content posting mechanics:
     > *"Cool @username, we're on it! 🚀 Generating your cinematic demo for [URL] now, we'll get back to you with the video link right here soon!"*

2. **Step 2: Submit Video Job via Pitch MCP API**
   - Trigger the Pitch MCP tool `create_demo_video` for the target URL.
   - Capture the returned `jobId`.

3. **Step 3: Track Job & Deliver Final Rendered Video S3 Link**
   - Poll the Pitch MCP `get_job` tool (via the `pitch` MCP server) until status
     is `COMPLETED`. When polling manually, sleep 5 minutes initially, then poll
     at 2-minute intervals. (The webhook's `/api/webhook/pitch` callback may also
     dispatch an opencode session on completion.)
   - Deliver the S3 video link as a second X reply **via agent-webbridge**
     (`Testing` profile), attaching the MP4 where practical / posting the direct
     link:
     > *"Here is your product demo @username generated by @trypitchdotco! Hope you enjoy it: https://s3.trypitch.co/trypitch/pitch/user_.../videos/.../final_with_cards.mp4 🎬"*

## Guardrails & operational rules

- **This flow is the real-time/delivery leg of the system.** The Rust webhook
  server (`./target/release/pitch-cli server`) receives X mention events at
  `/api/webhook/x` and **dispatches an `opencode run` session** that executes
  this skill end-to-end. Run `awb status` first; always post via the
  `agent-webbridge` `Testing` profile — never a headless X API client.
- Before any X write, run `./target/release/pitch-cli circuit-breaker`
  (stop if exit 1) and `./target/release/pitch-cli budget`.
- **Idempotency:** never double-reply to the same mention. The SQLite
  `mention_jobs` table tracks tweet ID → jobId → status (`pending → rendering →
  delivered | failed | no_url_found`) and prevents duplicates.
- If the mention has no valid URL, mark the job `no_url_found` and skip delivery.
- Queue for human review if a video render fails repeatedly (`failed`) instead of
  spamming retries.
- Read `.opencode/skills/x-growth/safety.md` and
  `.opencode/skills/x-growth/voice.md` before any public text; run receipts and
  delivery replies through the `humanizer` skill where practical (the <1s receipt
  is time-critical, so keep the template warm and on-brand).
- The receipt and delivery replies are allowed to be template-cliched by design
  (this is a bot product play for reach), but still human-warm, truthful, and
  within `.opencode/skills/x-growth/voice.md` approved claims about what
  @trypitchdotco does.

## Dispatcher & pipeline

- `./target/release/pitch-cli server` — the webhook listener on
  http://0.0.0.0:8790. Receives X mention events at `/api/webhook/x` and Pitch
  MCP completions at `/api/webhook/pitch`, and **spawns an `opencode run`
  session** (capped by `MAX_OPENCODE_SESSIONS`, logs under `data/sessions/`)
  that executes this skill.
- `./target/release/pitch-cli trigger` / `inbox` / `worker` are **gone** — the
  webhook dispatcher replaced the Rust mention pipeline.
- `./target/release/pitch-cli db jobs` — inspect the `mention_jobs` table.

## MCP tools (preferred)

- **`pitch` MCP server** (remote `https://api.trypitch.co/mcp`): `create_demo_video`,
  `get_job`, `get_credits` — use these instead of any CLI wrapper.
- **`xmcp` MCP server** (official X MCP via `xurl`): `mentions`, `search`, `me`
  — use for reads. For **writes** (posting replies), use the `agent-webbridge`
  `Testing` profile instead.
